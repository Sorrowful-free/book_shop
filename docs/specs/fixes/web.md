# Fixes: web

> Статус: done | Модуль: `apps/web` (без изменений backend-контрактов)

## F-W1. Счётчик корзины в шапке не обновляется после checkout/оплаты

### Проблема

После оформления и оплаты заказа бейдж `cartCount` в `AppHeader` продолжает
показывать старое число позиций, пока пользователь не перезагрузит страницу
или не совершит ещё одно cart-действие.

Корень — асинхронная очистка корзины: cart-service декрементит купленные
позиции по Kafka-событию `order.order.created` (F-K4,
`cart.service.ts::handleOrderCreated`), а `refreshCart()` в
`checkout.vue::placeOrder` вызывается синхронно сразу после ответа gateway —
**до** того, как consumer успевает применить событие. `GET /api/cart`
возвращает ещё не уменьшенную корзину, и `useState("cart")` остаётся
устаревшим на все последующие навигации.

Дополнительно: `pay()` в `checkout.vue` и `act("pay")` в `orders.vue` вообще
не вызывают `refreshCart` — после перехода на `/orders` бейдж гарантированно
stale.

### Ожидаемое поведение

- Сразу после успешного checkout и после оплаты бейдж отражает фактическое
  содержимое корзины (как правило — пустую или только позиции, добавленные
  после checkout, по семантике F-K4).
- Не полагаться на тайминг Kafka-consumer'а: гонка «refresh дошёл раньше
  события» не должна оставлять в UI протухшее число.

Рекомендуемый приём (на усмотрение исполнителя при соблюдении критериев):
оптимистичное обновление локального состояния — после успешного checkout
вычесть `goods[]` заказа из `useState("cart")` по той же позиционной
семантике, что и F-K4 (декремент `amount`, `<= 0` → удалить позицию), плюс
`refreshCart()` для сверки с сервером; `refreshCart()` также после `pay()` в
`orders.vue`. Это убирает гонку без polling'а и не добавляет задержек в UI.

### Acceptance criteria

- Unit/e2e web: после checkout `cartCount` равен 0 (при выкупе всей корзины)
  без перезагрузки страницы.
- После `pay` со страницы `/orders` бейдж обновлён.
- Существующее поведение бейджа при add-to-cart / remove не регрессирует
  (`useSession.spec`-уровень либо аналогичное покрытие).

### Out of scope

- Realtime-синхронизация корзины между вкладками/устройствами (SSE/WS);
  изменение момента очистки корзины на backend (F-K4-семантика остаётся).
