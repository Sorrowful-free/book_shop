> Статус: approved

> ревизия. Все блокеры и actionable-варнинги уже закрыты; здесь — оставшиеся
> ниты, оформленные как контракт на результат.

Эти документы — **не** «спеки сервисов» (см. `docs/specs/NN-*.md`), а
предметные спеки исправлений. Формат каждого пункта:

- **Проблема** — что именно неверно сейчас (доказуемо по коду/поведению).
- **Ожидаемое поведение** — нормативный контракт после фикса (что система
  ДОЛЖНА делать, без привязки к конкретной реализации).
- **Acceptance criteria** — проверяемые утверждения (given/when/then).
- **Out of scope** — что явно не входит.

## Общие ограничения (actionable для всех фикс-спек)

- Runtime portability: никаких `Bun.*`/`bun:*` в `src/` и `packages/` (AGENTS.md).
- gRPC-коды ошибок не меняются: валидация → `INVALID_ARGUMENT`, отсутствие
  сущности → `NOT_FOUND`, состояние → `FAILED_PRECONDITION`, auth →
  `UNAUTHENTICATED`/`PERMISSION_DENIED`. Сообщения могут меняться.
- Поведение, уже покрытое тестами, не должно регрессировать: полный
  `bun test` обязан оставаться зелёным.
- Env-контракт расширяется только аддитивно (новые переменные имеют дефолты
  или опциональны; существующие обязательные переменные не переименовываются).
- Новые env-переменные документируются в `.env.example` и README сервиса.
